# feat(energy): house electricity cost primitive (Plan 1)

## Summary

Orion can now put a dollar figure on its own GPU work, priced from the house's real Rocky Mountain Power meter data.

- Drop a Green Button export (the XML file from RMP's "Download my data") into a folder. The new `orion-energy` service turns it into hourly house kWh and publishes each hour on the bus.
- Each billing cycle is priced with the published Utah Schedule 1 tariff (in effect Aug 10, 2026). That includes the 400 kWh block step, summer/winter rates and riders. The result is a running "cycle so far" cost in dollars.
- Every settled GPU power intent gets two separate numbers that are never merged:
  - `estimated_run_cost_usd`: Orion's own meter reading times the *marginal* rate at that point in the cycle. This is the only number autonomy may ever read.
  - `house_share_cost_usd`: context only.
- Anything unknown is null plus an explicit reason, never $0. A billing cycle with holes in its meter data counts as unknown (Juniper's decision during execution). Runs priced before the utility data arrives are re-priced automatically when it lands.
- `orion-sql-writer` persists all three event kinds with idempotent "newest wins" upserts.

## Outcome moved

Before this, Orion had GPU power readings (watts and joules per settled intent) but no idea what they cost. Now the same GPU hour visibly costs more once the house is past 400 kWh in a cycle. The bill-replay eval pins that against a hand-computed bill: $0.0277 at 100 kWh into the cycle versus $0.0353 at 600 kWh.

## Metric quality gate record

1. **Provenance:**
   - `energy_kwh` comes from ESPI `IntervalReading.value × 10^powerOfTenMultiplier / 1000` (`orion/energy/espi.py:parse_espi`).
   - Run kWh comes from `PowerIntentSettledV1.actual_mean_watts − baseline_watts` over the window, or gross `energy_joules` when there's no baseline (`services/orion-biometrics/app/power_intent.py:summarize`, then `orion/energy/run_cost.py:_run_kwh`).
   - Dollars come from the published Schedule 1 blocks × riders (`config/energy/tariff.rmp_ut_sch1.2026-08-10.yaml`).
2. **Independence:** house kWh is the utility meter, an independent instrument. Run kWh is the GPU sampler, independent of the utility. House share is derived from both and is explicitly labeled context, not a new independent signal.
3. **Theory anchor:** marginal cost under increasing-block pricing. The price of the next kWh is set by cumulative usage so far in the cycle.
4. **Live data:** UNVERIFIED until a real Green Button export is dropped. The rest state is well defined and tested: no load gives 0 kWh intervals with a real $0 energy cost, and anything unmeasured or with holes gives null plus a gap reason. The live smoke confirmed the parse → publish path on the real bus with fixture data.
5. **Existing mechanism:** none. There was no prior utility, tariff, or household-dollar signal in the repo.
6. **Reversibility:** purely additive tables and channels. Stop the service and nothing else depends on it until Plan 2 adds a consumer behind a default-off flag.

## Review findings fixed

Each task went through a spec-and-quality review, then a whole-branch review at the end.

- **Missing flow direction or unit was guessed** (the plan's example defaulted to forward flow and Wh). That could count solar export as consumption.
  - Fix: a missing field now raises `EspiError`, and all bad values are wrapped as `EspiError`.
  - Evidence: `test_missing_flow_direction_raises` and related tests.
- **Tariff clamped NaN or negative kWh to $0.**
  - Fix: `TariffError` on non-finite or negative inputs and on malformed configs.
  - Evidence: `test_energy_tariff.py` NaN, inf and negative cases.
- **Holes in cycle data counted as zero kWh**, which could price a run in the cheaper block.
  - Fix (Juniper's decision): the cycle must be contiguous from its start, or the result is unknown and gets re-priced when data fills.
  - Evidence: ledger hole, fill and DST tests, plus the eval.
- **NaN settlement wattage produced a confident $0.00.**
  - Fix: non-finite inputs become `settlement_not_measured`.
  - Evidence: `test_energy_run_cost.py` NaN-baseline and NaN-mean tests.
- **Critical: real Green Button files were rejected.** The parser took the first `related` link, which in the Green Button Alliance layout is the IntervalBlock link.
  - Fix: resolve the related href that is an actual ReadingType in the feed.
  - Evidence: the new `espi_gba_link_order.xml` fixture test.
- **A partial first cycle was silent.** Usage was published but nothing accrued, with no explanation.
  - Fix: an `energy_cycle_incomplete` warning, plus a README operator step and the decision recorded in the spec.
  - Evidence: a service test with caplog.
- **O(n²) cache purge on re-dropped exports.** Measured at about 45 s of event-loop stall for a 2-year re-drop.
  - Fix: cache keyed per cycle, plus a dirty-cycle set.
  - Evidence: a perf guard test of 17,520 intervals re-upserted in under 5 s.
- **`.env` could be baked into the image.**
  - Fix: `services/orion-energy/Dockerfile.dockerignore`.
  - Evidence: the built image has no `/app/.env`.
- **Minor fixes:**
  - The fresh `computed_at` is now taken inside the lock.
  - Per-file `OSError` handling in the inbox.
  - README notes on newest-drop-wins, copying files in under a temp name, in-memory pending state, and best-effort publishing.

## Risks / concerns

- **Medium: real RMP export untested.** No real RMP export has been parsed yet. The parser is covered by synthetic and Green Button Alliance-shaped fixtures. First real drop: watch `energy_inbox_parsed` or `energy_inbox_parse_failed`, and check `inbox/failed/`.
- **Medium: three rider columns not confirmed.** Three stage-2 rider columns are `column_verified: false`, and taxes aren't modeled (`cost_basis: pre_tax`). Plan 2's bill reconciliation measures the actual gap against the real bill.
- **Low: pending re-pricing is lost on restart.** Pending run-cost re-pricing lives in memory, so a restart loses it. Those runs keep their first estimate, which is null plus a reason rather than a wrong number. This is documented in the README.
- **Low: accrual waits for a full cycle.** The first partial cycle accrues nothing unless the export starts at the cycle start. Mitigation: the `energy_cycle_incomplete` log and the README step.
- **Low: remaining Minors.** Polish items from the reviews are tracked as follow-ups:
  - error types for malformed tariff configs;
  - untested proration and zero-window edge cases;
  - stale redelivery not logged in sql-writer.
