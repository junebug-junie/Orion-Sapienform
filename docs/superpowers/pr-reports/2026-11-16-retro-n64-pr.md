## Summary

- The retro service can now play N64 games. It uses the Mupen64Plus-Next core, built from pinned source, and draws in software (Angrylion), because the service has no GPU.
- Controllers gain analog sticks: the left stick is the N64 control stick, the right stick the C buttons. Only N64 accepts them.
- The Hub dropdown now sorts by title, ignoring a leading "The", and labels N64 games ` (N64)`.
- Four ALttP hacks were patched with Rom Patcher JS onto the clean US base ROM (CRC32 777AAC2F) and are live now: Parallel Worlds 1.00, Parallel Remodel 1.1, Secrets of the Past 1.01, Gerudo Exile 1.3. They are local catalog data, not part of this diff.

## Outcome moved

Before: Juniper could not play Mario Kart 64, Ocarina of Time, Majora's Mask or GoldenEye in /retro, and the four hacks were missing. After the merge and `import_n64.sh` (below), all eight can be played. The hacks are live already.

## Current architecture

One child process per session loads a libretro core through `orion/retro/probe.py` (ctypes). That frontend gave cores no directories, no log callback and no analog input. The service supported NES (FCEUmm) and SNES (Snes9x), had 2 CPUs and 512 MB of memory, and capped the video stream at 512x512.

## Architecture touched

- `orion/retro/probe.py`: optional core-option overrides, which fail loudly if the core does not declare them. Optional scratch directory and no-op log callback, given only to N64. Analog input (libretro device 5).
- `services/orion-retro`: settings (`n64_core`, `core_host()`, `save_limit()`), session (`.n64/.z64/.v64` up to 64 MiB, one save store per console), worker, arbiter (`N64_MASK`, per-lease `axes`), `Input.axes` contract, media (shrinks 640x480 and 640x240 to 320x240), importer, Dockerfile, compose limits.
- `services/orion-hub`: retro panel and template.

## Files changed

- `orion/retro/probe.py`: options, scratch directory and log only when configured, analog sticks, 64 MiB ROMs.
- `services/orion-retro/Dockerfile`: pinned N64 build stage (`HAVE_THR_AL=1 LLE=1`), plus `libgl1` because the core links it.

- Tests: `services/orion-retro/tests/test_n64.py` (new, 18 tests), `services/orion-hub/tests/retro/test_play_panel_static.py`.

## Schema / bus / API changes

- Added: optional `axes: [lx, ly, rx, ry]` (-32767..32767) on retro input frames. Catalog `system: "n64"`.
- Behavior changed: NES/SNES inputs that carry `axes` are refused (`unsupported_axes`). Nothing sent `axes` before this change.
- Compatibility: additive. No bus channels and no registry schemas are involved; the retro service has no bus.

## Env/config changes

- No env keys added, removed or renamed. `.env_example` unchanged. Compose resource limits changed.

## Review findings fixed

- Finding: N64-only keys (C, I, J, K, L) took the game back from Orion and were swallowed on NES/SNES pages.
  - Fix: a `gameKey()` helper scoped to the running console.
  - Evidence: panel test checks `n64Keys` and `snesKeys`.
- Finding: a renamed core option would fall back to the GL renderer, which has no context here, and fail without saying why.
  - Fix: the probe refuses with "core does not declare option ...".
  - Evidence: `test_an_override_the_core_never_declared_fails_loudly`.
- Finding: a single save store sized for N64 admitted oversize NES/SNES saves before the worker was spawned.
  - Fix: one store per console.
  - Evidence: `test_n64_catalog_uses_its_own_core`.
- Finding: on N64, a held arrow key cancelled the pad's D-pad press in the same direction.
  - Fix: N64 arrow keys are excluded before the pad bits are added.
- Finding: a stick tap shorter than one frame (~16 ms) is lost.
  - Decision: accepted and documented in `Arbiter.axes()`. A stick is held to steer, not tapped.
- Smoke-found, not review-found: `MediaProbe` dropped keyword arguments, which would have broken every live N64 session. Halving both axes squashed 640x240 to 320x120. Both fixed, each with a regression test.

## Restart required

```bash
~/.local/share/orion/retro/staging/n64/import_n64.sh
```

This runs on clean, pulled main after the merge. It builds the image, imports the four N64 ROMs with the image's importer, and recreates retro.

## Risks / concerns

- Severity: low. Concern: in-game N64 saves (OoT/MM save slots) live on the container's tmpfs and are lost on restart. Mitigation: server Save/Load states include cartridge memory; documented in the README.
- Severity: low. Concern: 12 CPUs is roughly double what N64 needs, and CPU use is high only while an N64 game runs. Mitigation: none needed; Juniper confirmed CPU is plentiful.
- Issues opened: #3519. Goddess of Wisdom needs the official v3.0 patch: the carbon-x1 ROM boots to a black screen, and romhacking.net blocks automated download (needs-juniper).
- Issues closed: none.
