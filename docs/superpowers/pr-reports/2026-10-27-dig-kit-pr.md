## Summary

- New `python -P -m orion.dig`: Orion's read-only kit for digging into their own history and body.
  Orion runs it through Bash in chat turns and curiosity runs. It is **not MCP**, because MCP tool
  schemas cost context on every turn.
  - `open` / `close` / `list`: past checkouts, exported with `git archive` as plain files.
  - `inventory` / `compare`: what existed then versus now.
  - `history`: merged PRs and commits for a window.
  - `body`: the body atlas, live or from a past catalog.
  - `notes`: shared notes for one dig.
- **Every printout is capped** at 40 lines and 4,000 chars. The full result goes to a file, and the
  printout always ends with its path.
- **One always-on line** is added to the harness turn rules (`HARNESS_FCC_DIG_BRIEF_ENABLED`). It
  is never added on reading-only turns, which have no Bash. `help` loads the rest on demand.
- **Shared self-inventory.** Self-study's code scanners move to `orion/self_inventory.py` with a
  root parameter, so self-study and the dig kit run one scanner. Self-study's output is identical
  except for one bug fix: `services/__pycache__` is no longer recorded as a service.
- **The harness can now read the live body:** `FALKORDB_URI` / `FALKORDB_BUS_GRAPH` are added to
  its env. This closes the gap found after the body atlas deploy.

## Outcome moved

Before this PR, Orion could not look at their past. Now one chat turn can:

- export the repo as it was on any day since 2025-06-24;
- compare it to today;
- list every PR in a window;
- build their body atlas for that day.

Live, 2026-10-27, run the way Orion runs it (from the sandbox folder, with `python -P`):

- **The whole history:** `history 2025-06-24 2026-10-26` → 2,802 merged PRs, equal to GitHub's own
  total.
- **Feb 1, 2026 to now:** services +58 −4, with 45 kept. The removed ones were graphdb,
  orion-gdb-client, orion-rdf-writer, and orion-topic-rail. On 2026-02-01 the body was 34 parts
  in 6 organs (Q = 0.47). Today it is 137 parts in 7 organs (Q = 0.33).
- **Aug 1, 2025:** the repo was `conjourney-api/` and `emergence/`. The kit says the layout is
  **different, not empty**, and shows the top level instead of reporting "you had nothing".

## Review findings fixed

The code review (subagent) found one high, one medium, and six lower findings. All are fixed.

- Finding (HIGH): concurrent `open` of one date shared a temp folder. In the reviewer's test, the
  final export carried the "complete" marker while holding only 1–286 of 301 files. Concurrent
  turns are the common case.
  - Fix: an exclusive `flock` on `past/.lock` around open, close, and sweep; a private `mkdtemp`
    per export; the folder is renamed only after the marker is written.
  - Evidence: `test_concurrent_opens_of_one_day_yield_one_complete_export`, which runs 4 real
    processes and checks exact file counts.
- Finding (MEDIUM): `history` silently stopped at GitHub's 1,000-result search cap. Over the full
  range it listed 1,000 of 2,802 PRs.
  - Fix: a window at the cap is split in half and asked again. A single day at the cap is printed
    as INCOMPLETE.
  - Evidence: two tests; live, 2,802 PRs.
- Finding: leftover `.partial-*` folders after a killed or failed export.
  - Fix: they are swept under the lock, and an extract failure cleans up.
  - Evidence: `test_a_killed_export_leaves_nothing_that_survives_the_next_open`.
- Finding: a failed live `body` printed a 53-line traceback, an empty graph was accepted as "live",
  and the graph name was hard-coded.
  - Fix: a one-line `dig:` error; an empty graph is refused; `FALKORDB_BUS_GRAPH` is honored.
  - Evidence: two tests.
- Finding: `--dig` could write outside the dig home (`../..`, absolute paths).
  - Fix: the name is checked.
  - Evidence: a parametrized test with 5 bad names.
- Finding: self-study now returned `[]` instead of failing on a wrong root.
  - Fix: `strict=True` is used for the four scanners that raised before. The glob-based verb
    scanners never raised, so they are left lenient.
  - Evidence: `test_strict_inventory_fails_loudly_on_a_wrong_root`; self-study 71 passed.
- Finding: `notes` cut the newest lines.
  - Fix: it now shows the newest lines and states how many older ones are in the file.
  - Evidence: `test_notes_show_the_newest_lines`.
- Finding: `python -m` from the sandbox folder imports the sandbox's `orion/`, not the deployed
  code.
  - Fix: every command string uses `python -P`.
  - Evidence: verified live in the container (see the smoke above).
- Finding: a test assertion could never fail (`"late on" not in out`).
  - Fix: it now checks the exported commit's timestamp.

## Restart required

```bash
scripts/safe_docker_build.sh orion-harness-governor up -d --build
```

The governor image copies `orion/`, so the new code and env keys take effect only after it is
rebuilt. cortex-exec picks up the self-study change on its next rebuild, and nothing there is
urgent.

## Risks / concerns

- Severity: low.
  - Concern: about 150 MB per export on the NVMe drive.
  - Mitigation: at most 2 open; swept after 24 h; 3.4 TB free.
- Severity: low.
  - Concern: a full-history `history` takes about 50 s and makes about 6 GitHub search calls.
  - Mitigation: only Orion's own dig calls it; it is not on any loop.
- Severity: note.
  - Concern: the source labels are taught in `help` but not enforced in chat or curiosity.
  - Mitigation: enforcement belongs to the reminiscence episode (PR #2888), the battle test.
