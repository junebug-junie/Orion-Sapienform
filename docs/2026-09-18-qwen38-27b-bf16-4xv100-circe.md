# Qwen3.8-27B BF16 on 4× Tesla V100 32GB

**Live local run — 2026-09-18.**
**Status:** loaded, served tokens, decode measured. Not wired into Orion chat.

This is a hardware + llama.cpp field note for the full-precision 27B, same shape as the DeepSeek-V4.1-Flash note from the same evening. Numbers below come from one host (`circe`), one stock image, one GGUF pack, and four timed completions (thinking on, then instruct / thinking off). Where we did not measure something, it is marked **unverified**.

This is **not** `orion-atlas-llamacpp-chat`. Chat is still down (`Exited 137`). The process listening is a standalone smoke on **8098**.

---

## Headline

It runs, and it is not crawling.

- **Load from NVMe:** ~49 seconds to `/health` (weights already on the Lexar)
- **Decode (thinking on):** **15.69 tok/s** then **15.77 tok/s**
- **Decode (instruct / thinking off):** first request after reload **12.00 tok/s** (CUDA warmup), then **15.14 tok/s**
- **Prefill:** 26–45 tok/s once warm. First instruct request after reload was 1.58 tok/s / 19 s — warmup, not a mode effect.
- **VRAM:** ~14.2–15.7 GiB per 32GB card. Lots of unused room.
- **Why it feels fast vs DeepSeek:** this is a dense 27B sitting in VRAM. No MoE expert fetch. DeepSeek’s best measured decode tonight was 3.36 tok/s.

Turning thinking off does **not** make tokens cheaper. Same ~15 tok/s once warm. What changes is where the tokens go: thinking-on hid most of a 256-token budget; instruct wrote the whole reply and stopped on EOS.

**Currently listening:** instruct / non-thinking card (`temperature=0.7`, `top_p=0.80`, `top_k=20`, `min_p=0.0`, `presence_penalty=1.5`, `repetition_penalty=1.0`). `--reasoning-budget 0`, `enable_thinking=false`. `/props` reports `reasoning_format=none`.

## Serve recipe (what is listening now)

First boot used the thinking card (`--temp 1.0 --top-p 0.95`, `reasoning_effort=xhigh`). Then we reloaded with the instruct overlay (temp yaml on Circe `/tmp/llm_profiles_bf16_instruct.yaml`, not a git profile change):

```text
llama-server \
  -m /models/gguf/BF16/Qwen3.8-27B-BF16-00001-of-00002.gguf \
  --host 0.0.0.0 --port 8080 \
  --ctx-size 131072 \
  --n-gpu-layers 99 \
  --threads 16 \
  --parallel 2 \
  --batch-size 1024 \
  --jinja \
  --reasoning-format deepseek \
  --chat-template-kwargs {"enable_thinking":false} \
  --reasoning-budget 0 \
  --no-context-shift \
  --split-mode layer \
  --tensor-split 1,1,1,1 \
  --n-predict 16384 \
  --temp 0.7 --top-k 20 --top-p 0.8 --min-p 0.0 --presence-penalty 1.5
```

Host log said it skipped `--reasoning off` (`build 0 (not supported)`). Budget 0 + `enable_thinking=false` was enough: both instruct replies had `reasoning_len=0` and `/props` `reasoning_format=none`. llama.cpp itself warned that `enable_thinking` via kwargs is deprecated in favor of `--reasoning off`.

`--flash-attn` is off (Volta). `--parallel 2` splits the 131072 context into **two 65536-token slots**. `/props` reports `n_ctx=65536` per slot. Train window is 262144; we are serving half of that, then splitting it again.

After load, VRAM was:

| GPU | Used |
| --- | ---: |
| 0 | 15266 MiB |
| 1 | 14527 MiB |
| 2 | 16110 MiB |
| 3 | 15480 MiB |

~61–73 GiB free across the four 32GB cards. Comfortable. We did not OOM. Concurrent-slot throughput with both slots busy is **unverified**.

## Bottleneck (this is the result)

This is compute-bound enough to be usable, and not stall-bound the way Flash was.

```text
DeepSeek-V4.1-Flash (cache 64)   3.36 tok/s   ~67% expert-load stall
Qwen3.8-27B BF16                 15.7 tok/s   weights resident, no expert fetch
```

The cards still look quiet on `nvidia-smi` (12–26% SM, ~38–88 W). Layer split across four Voltas does that. They are not waiting on disk.

What *does* steal the reply when thinking is on: **reasoning at `xhigh`**. The first 256-token call spent most of the budget thinking. Instruct mode removes that. It does not move tok/s.

## What we would tell someone else on Volta

1. **Stock `server-cuda-b10398` loads this.** No fork, no `--moe-stream`.
2. **Keep `--flash-attn off` on V100.** Same rule as every other Circe card tonight.
3. **Four 32GB cards is comfortable for BF16 27B.** ~15 GiB/card after a 131K / 2-slot boot.
4. **Expect ~16 tok/s**, not 3. That is the whole point of leaving DeepSeek.
5. **`xhigh` thinking eats `max_tokens`.** Instruct mode does not make tokens cheaper (~15 tok/s either way). It just writes the reply and stops.
6. **This smoke is not chat.** `orion-atlas-llamacpp-chat` is still dead on 8011. Pointing Orion at 8098 is a separate step.
