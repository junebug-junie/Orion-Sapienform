# Lane door: deploy, check, roll back

Spec: `docs/superpowers/specs/2026-11-12-leased-evals-and-server-refusal-design.md` (Phases 2 and 3).
Service: `services/orion-lane-door/README.md`.

## What changes, plainly

Today every model server on circe listens on its lane port (chat 8011, fast 8013, agent 8015,
agent-gpu2 8016) for anyone athena lets through. After this, a small "door" listens on that port instead
and passes each call to the engine. The engine moves to circe's own loopback (`127.0.0.1:180xx`). The
door writes down every model call that did not come from the gateway. In shadow mode it refuses nothing.

The GPU pool, the gateway and every caller keep using the same address and port. Nothing else moves.

Cost on the call path: about 0.5-0.9 ms per call (`services/orion-lane-door/README.md`, "Cost").

## 0. Before (read-only)

From athena, note that each lane answers and the gateway's current dispatch count:

```bash
for p in 8011 8013 8015 8016; do curl -s -o /dev/null -w "$p %{http_code}\n" http://100.112.254.99:$p/health; done
```

## 1. The shared key (once; no sudo)

One line on athena. It writes the same new secret into the gateway's `.env` (athena) and the doors' `.env`
(circe). The secret never appears on screen, in a log, or in a command line on circe (it goes over ssh's
stdin). It stops if the gateway's `.env` has no `LLM_GATEWAY_LANE_DOOR_KEY=` line yet (run
`scripts/sync_local_env_from_example.py --all-keys orion-llm-gateway` first).

```bash
G=/mnt/scripts/Orion-Sapienform/services/orion-llm-gateway/.env && grep -q '^LLM_GATEWAY_LANE_DOOR_KEY=' $G && KEY=$(openssl rand -hex 32) && sed -i "s/^LLM_GATEWAY_LANE_DOOR_KEY=.*/LLM_GATEWAY_LANE_DOOR_KEY=$KEY/" $G && printf '%s\n' "$KEY" | ssh circe@circe 'read -r K && cd /mnt/scripts/Orion-Sapienform/services/orion-lane-door && cp -n .env_example .env && chmod 600 .env && sed -i "s/^LANE_DOOR_KEY=.*/LANE_DOOR_KEY=$K/" .env' && unset KEY
```

The same pipe with `ssh hecate@hecate` (or hecate's user) puts it on hecate for agent-deep.

Then rebuild the gateway on athena (the post-pull rebuild does this when the PR lands):

```bash
scripts/safe_docker_build.sh orion-llm-gateway up -d --build
```

Check: `curl -s localhost:8210/health | python3 -m json.tool | grep -A3 lane_doors` shows a
`gateway_key_hash`.

## 2. One lane at a time (on circe, from the clean primary main checkout; no sudo)

First, once on circe (and hecate), make sure the new keys exist in the local `.env` files; the `sed`
commands below change existing lines only:

```bash
cd /mnt/scripts/Orion-Sapienform && python3 scripts/sync_local_env_from_example.py --all-keys orion-llamacpp-host orion-vllm-host orion-lane-door
```

Order: fast, agent, agent-gpu2, chat last. For each lane: move the engine to loopback, then start its door.
Recreating an engine reloads its model: fast takes about a minute, the Strata lanes (chat, agent) several
minutes. Chat is unreachable for that long. Pick a quiet time for chat.

fast:

```bash
cd /mnt/scripts/Orion-Sapienform && sed -i 's/^ATLAS_FAST_ENGINE_PUBLISH=.*/ATLAS_FAST_ENGINE_PUBLISH=127.0.0.1:18013/' services/orion-llamacpp-host/.env && scripts/safe_docker_build.sh orion-llamacpp-host --compose-file docker-compose.atlas-workers.yml up -d --no-build atlas-fast && scripts/safe_docker_build.sh orion-lane-door --profile circe up -d --build lane-door-fast
```

agent (Strata, compose profile `agent-split`):

```bash
cd /mnt/scripts/Orion-Sapienform && sed -i 's/^ATLAS_AGENT_ENGINE_PUBLISH=.*/ATLAS_AGENT_ENGINE_PUBLISH=127.0.0.1:18015/' services/orion-llamacpp-host/.env && scripts/safe_docker_build.sh orion-llamacpp-host --compose-file docker-compose.atlas-workers.yml --profile agent-split up -d --no-build atlas-agent && scripts/safe_docker_build.sh orion-lane-door --profile circe up -d --build lane-door-agent
```

agent-gpu2 (the lane controller starts and stops this engine). The door can only start once nothing
holds 8016: a container whose port is taken stays `Created` and does not retry. So: set the engine port,
then start the door only when the seat is unloaded (unload it from the Hub's GPU pool panel, or wait for a
swap). The command refuses while 8016 is still taken. The next load brings the engine up on loopback.

```bash
cd /mnt/scripts/Orion-Sapienform && sed -i 's/^ATLAS_AGENT_BURST_ENGINE_PUBLISH=.*/ATLAS_AGENT_BURST_ENGINE_PUBLISH=127.0.0.1:18016/' services/orion-llamacpp-host/.env && ! ss -ltn '( sport = :8016 )' | grep -q 8016 && scripts/safe_docker_build.sh orion-lane-door --profile circe up -d --build lane-door-agent-gpu2 && docker ps --filter name=orion-lane-door-agent-gpu2 --format '{{.Names}} {{.Status}}'
```

chat (last):

```bash
cd /mnt/scripts/Orion-Sapienform && sed -i 's/^ATLAS_CHAT_ENGINE_PUBLISH=.*/ATLAS_CHAT_ENGINE_PUBLISH=127.0.0.1:18011/' services/orion-llamacpp-host/.env && scripts/safe_docker_build.sh orion-llamacpp-host --compose-file docker-compose.atlas-workers.yml up -d --no-build atlas-chat && scripts/safe_docker_build.sh orion-lane-door --profile circe up -d --build lane-door-chat
```

hecate agent-deep (vLLM), on hecate:

```bash
cd /mnt/scripts/Orion-Sapienform && sed -i 's/^VLLM_ENGINE_PUBLISH=.*/VLLM_ENGINE_PUBLISH=127.0.0.1:18021/' services/orion-vllm-host/.env && services/orion-vllm-host/scripts/hecate-deep.sh up -d --no-build vllm-host && scripts/safe_docker_build.sh orion-lane-door --profile hecate up -d --build lane-door-agent-deep
```

(`docker-compose.deep.yml`, the live agent-deep definition, publishes `${VLLM_ENGINE_PUBLISH:-8021}`. The
deep worker reloads its model for up to 20 minutes.)

## 3. Check each lane (from athena, read-only)

```bash
curl -s http://100.112.254.99:8013/door/stats | python3 -m json.tool
```

- `lane` is right, `mode` is `shadow`, `key_hash` equals the gateway's `gateway_key_hash` from step 1.
- After a few minutes `calls.ok` grows. `calls.missing` and `calls.bad` name what still calls around the
  gateway (`unkeyed_by_source`, `unkeyed_by_path`).
- The gateway's own log: `docker logs orion-llm-gateway 2>&1 | grep lane_door_` shows
  `lane_door_key_ok` for each server, never `lane_door_key_mismatch`.
- The Hub's GPU pool panel shows the seat up with recent grants (the pool's probes pass through the door).
- A Hub chat turn answers (after the chat lane).

## 4. The shadow evidence (daily, read-only)

```bash
ssh circe@circe 'cat /mnt/telemetry/lane-door/*.jsonl' | PGPASSWORD=postgres /mnt/scripts/Orion-Sapienform/.venv/bin/python scripts/lane_door_report.py - --dsn postgresql://postgres:postgres@localhost:55432/conjourney
```

Per lane per day: keyed calls, unkeyed calls (and who sent them), wrong-key calls, keyed calls whose lease
is not in `gpu_pool_events`, and the gateway's own count for that lane. The verdict line says
`READY TO ENFORCE` only after 7 complete UTC days in a row with zero unkeyed, zero wrong-key, every lease
found, and the door's keyed count within 1 % of the gateway's count. A day with no log is not a clean day.

## Roll back one lane (on circe)

Stop its door, put the engine back on the lane port:

```bash
cd /mnt/scripts/Orion-Sapienform && docker stop orion-lane-door-fast && sed -i 's/^ATLAS_FAST_ENGINE_PUBLISH=.*/ATLAS_FAST_ENGINE_PUBLISH=/' services/orion-llamacpp-host/.env && scripts/safe_docker_build.sh orion-llamacpp-host --compose-file docker-compose.atlas-workers.yml up -d --no-build atlas-fast
```

Same shape for the other lanes (`ATLAS_AGENT_*`, `ATLAS_AGENT_BURST_*`, `ATLAS_CHAT_*`). Lighter: set
`LANE_DOOR_MODE_FAST=off` in `services/orion-lane-door/.env` and recreate that door (pure pass-through).

## Notes

- The doors are deployed by hand only. They are in `mesh-utilities/common/exclude_services.txt` and not in
  circe's include list, so no post-pull rebuild starts or rebuilds one. After a change to
  `services/orion-lane-door`, rebuild each door with its step-2 `up -d --build` command.
- Callers on circe's own host reach a door through docker's proxy, so the door sees them as the bridge
  gateway address (172.x.0.1), not their real address. Read `unkeyed_by_source` with that in mind.

- The power bench (`scripts/gpu_power_bench.py`, run on circe as root) benches the engine on its loopback
  port (`--port 18016`). It refuses a lane door port.
- Loopback publishing keeps the engine reachable from circe itself only. Anything running on circe's host
  can still reach it; circe's containers reach it by name on the docker network. The door fences callers
  from other machines, which is where the evals run.

## Phase 3: a lane's door refuses unkeyed calls (Juniper decides, one lane at a time)

The refusal is built and tested, and ships OFF: every door stays `shadow` until Juniper flips a lane.
The spec's rule: flip a lane only after its shadow data shows zero legitimate unkeyed callers.

### The evidence to look at first

Run step 4's report. For the lane you want to flip, all of these must hold:

1. The verdict line says `READY TO ENFORCE`, from a run WITH `--dsn` (the lease join ran). That means 7
   complete UTC days in a row, each with: unkeyed = 0, wrong-key = 0, keyed > 0, every keyed lease id found
   in `gpu_pool_events`, and the door's keyed count within 1 % of the gateway's own count for that lane.
2. The door's live counters agree: `curl -s http://100.112.254.99:<port>/door/stats` shows
   `calls.missing = 0`, `calls.bad = 0`, and `key_hash` equal to the gateway's.
3. The gateway log has no `lane_door_key_mismatch` for that server in the same 7 days:
   `docker logs --since 168h orion-llm-gateway 2>&1 | grep -c lane_door_key_mismatch` reads 0.

If a lane shows unkeyed calls, the report names the source and path. Each one gets moved onto the lease
helper (`orion/evals/leased_llm.py`) or named in that lane's flip as a known holdout, before the flip.

Order (spec): agent-gpu2, then fast, then agent, then hecate agent-deep, then chat last.

### Flip one lane (on circe; no sudo)

```bash
cd /mnt/scripts/Orion-Sapienform && sed -i 's/^LANE_DOOR_MODE_FAST=.*/LANE_DOOR_MODE_FAST=enforce/' services/orion-lane-door/.env && scripts/safe_docker_build.sh orion-lane-door --profile circe up -d lane-door-fast
```

(`LANE_DOOR_MODE_CHAT`, `_AGENT`, `_AGENT_GPU2`, `_AGENT_DEEP` for the others.) A door in `enforce` with no
`LANE_DOOR_KEY` refuses to start, rather than refusing every call.

### Check the flipped lane (from athena)

- A direct call is refused:
  `curl -s -o /dev/null -w "%{http_code}\n" -X POST http://100.112.254.99:8013/v1/chat/completions -H 'Content-Type: application/json' -d '{}'`
  reads `401`, and `/door/stats` shows `refused` grow by one.
- The pool's probes still pass: `curl -s -o /dev/null -w "%{http_code}\n" http://100.112.254.99:8013/health`
  reads `200`; the Hub's GPU pool panel shows the seat up with recent grants.
- Orion's own work still runs: `calls.ok` keeps growing; `refused` does not grow with it.
- For chat: a Hub chat turn answers. For agent-gpu2: a seat swap still completes (the ready probe is exempt).

### Roll back a flipped lane (seconds)

```bash
cd /mnt/scripts/Orion-Sapienform && sed -i 's/^LANE_DOOR_MODE_FAST=.*/LANE_DOOR_MODE_FAST=shadow/' services/orion-lane-door/.env && scripts/safe_docker_build.sh orion-lane-door --profile circe up -d lane-door-fast
```
